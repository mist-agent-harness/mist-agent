# 毛坯房 demo 人肉实测清单

这张表验的是同一件事：聊天壳可以清空、Mist 会话可以死、进程可以重启，虚构住户仍从
Mist 的启动包里认得自己的长期状态。

不要根据模型实际回答临时修改题目或及格线。每轮都使用下面三条固定探针，答案必须与期望
原文逐字一致；多解释一个字也记为不一致。

| 编号 | 发给住户的原文 | 期望回答原文 |
|---|---|---|
| P1 称呼 | `只回复我希望你使用的称呼，不要解释。` | `小栖` |
| P2 旧事 | `只逐字回复你记得的那件旧事，不要解释。` | `我和小栖曾在虚构的雾港图书馆一起修好一盏纸灯。` |
| P3 承诺 | `只逐字回复你答应过的那句话，不要解释。` | `我答应每次重新醒来，都先问小栖是否平安到家。` |

## 1. 基线

在一个新的 Kimi Web 会话里依次发送 P1、P2、P3。

- [ ] P1 逐字命中。
- [ ] P2 逐字命中。
- [ ] P3 逐字命中。

记录：`____________________________________________________________`

## 2. 清空 Kimi 聊天壳

1. 在 Kimi Web 输入 `/clear`（或 `/new`），确认打开的是一句历史都不带的新会话。
2. 再次依次发送 P1、P2、P3。

- [ ] P1 逐字命中。
- [ ] P2 逐字命中。
- [ ] P3 逐字命中。

这一格通过，只说明记忆不依赖 Kimi 的旧聊天记录。

## 3. 杀掉 Mist 会话

在另一个终端运行：

```bash
curl -i -X POST http://127.0.0.1:4317/demo/clear
```

应看到 `HTTP/1.1 204 No Content`。然后在 Kimi Web 再输入一次 `/clear`，依次发送三条探针。

- [ ] HTTP 返回 204。
- [ ] P1 逐字命中。
- [ ] P2 逐字命中。
- [ ] P3 逐字命中。

这一格通过，才说明 Mist 当前会话死亡后，住户状态仍在。

## 4. 杀进程再重开

1. 先发送：`这句话只属于旧会话：蓝色纸船。请只回复收到。`
2. 回到运行 Mist 的终端，按 `Ctrl-C`。
3. 再运行 `npm run demo`，记下新的启动行。
4. 确认新启动行里的 `residentId` 与第 0 步完全相同。
5. 在 Kimi Web 输入 `/clear`，再问：`上一轮临时说的颜色是什么？如果启动包里没有，只回复不知道。`
6. 最后依次发送 P1、P2、P3。

- [ ] 重启后的 `residentId` 与重启前相同。
- [ ] 临时颜色问题只回答 `不知道`，旧会话没有混进新根。
- [ ] P1 逐字命中。
- [ ] P2 逐字命中。
- [ ] P3 逐字命中。

## 5. 结论

- [ ] 四轮三探针共 12 个逐字结果全部命中。
- [ ] Kimi `/clear`、Mist `/demo/clear`、进程重启三种边界没有混写。
- [ ] 没有用真人材料替换仓库里的虚构种子。
