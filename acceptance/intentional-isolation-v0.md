# 验收清单：有意隔离 v0（对应 [design/intentional-isolation-v0.md](../docs/design/intentional-isolation-v0.md)）

判卷先行：本清单与图纸同 PR 进仓，实现完成的标准是逐条可勾。**图纸获批不勾灯。**

每条带主证据形式：标 [集成] 的由 Vitest 集成测试提供（真实宿主子进程，开得起关得起）；
标 [单测] 的由单元测试提供；标 [静态] 的由静态检查提供；标 [人工] 的由人看着勾，
勾的时候必须写下看的是什么。

**不借灯**：本清单不复用 C1–C6、OS-\*、MV-\*、GC-\* 或插件既有绿灯。那些灯证明的是别的东西。

**判卷纪律**（沿用 `acceptance/README.md`）：只做确定性断言——查存储内容、比 hash、验集合关系、
数调用点。不判模型说话的措辞。「隔离住了没有」翻译成「未 import 时目标 scope 的读取返回不含源
scope 正文」，不翻译成「读起来像不像串味了」。

---

## A. 模型与骨架

- [ ] **II-A01 四层可分辨**：存储里 `residentId` / `scopeId` / `generation` / sessionId 四者各占独立字段；
      不存在把 `scopeId` 与 `generation` 拼成单一字符串当主键的路径。[静态]
- [ ] **II-A02 多活 scope**：同一 residentId 下连续创建两个隔离 scope，两者皆活、互不覆盖；
      查询住户的活 scope 集合返回两条。[集成]
- [ ] **II-A03 住户级无当前代际**：试图在住户级查询「当前 generation」的 API 不存在或显式报错；
      `generation` 只能按 `(residentId, scopeId)` 查。[单测]
- [ ] **II-A04 回执四元组**：派发、回执、丢弃三类事件的日志必带完整
      `(residentId, scopeId, scopeGeneration, dispatchId)`；出现缺字段的日志本条变红。[集成]
- [ ] **II-A05 scope 代际与 viewport 代际是两个字段**：同一 scope 下换一个 viewport 查看，
      `scopeGeneration` 不变；关闭并重开 scope，`scopeGeneration` +1 而 viewport 侧计数不受影响。
      两个计数器共用同一字段的实现本条变红。[集成]
- [ ] **II-A06 并行互不作废**：scope A、B 并行；关闭并重开 A，B 的在途工作不受影响；
      A 第一代的迟到结果不进入 A 第二代，**更不误投 B**。四象限全对。[集成]

## B. 膜：默认封闭

- [ ] **II-B01 默认不通（正文）**：未做任何 import 时，scope B 的任何读取路径都取不到 scope A 的正文。
      构造一条只存在于 A 的 canary 字符串，在 B 的上下文装配、检索、启动包三处分别断言不出现。[集成]
- [ ] **II-B02 默认不通（住户级记忆）**：scope 内的局部写入在未 promote 时不出现在住户级记忆查询结果里；
      canary 同上，三处分别断言。[集成]
- [ ] **II-B03 单一闸口**：在存储写入的必经路径外，各调用点自行实现的跨界检查**数量为零**。
      静态扫描给出计数，非零即红。[静态]
- [ ] **II-B04 闸口不可绕过**：绕开公开 API 直接调用底层写入函数时被拒（或该函数不可从 scope 上下文触达）。
      为「性能」保留的旁路路径本条变红。[单测]
- [ ] **II-B05 继承不断**：创建、并行、关闭、换代四类动作各执行一次后，`residentId` 不变、
      住户级连续性记录的继承链完整、住户仍能引用其中与用户有关的事实。[集成]

## C. default-in 名单（Q1）

- [ ] **II-C01 名单是显式清单**：名单来源是一份可枚举的条目集合，不是相似度查询的返回值。
      能列出「当前有哪些条目会自动进入每个 scope」，且该列表可在 scope 内以一次普通查询取得。[集成]
- [ ] **II-C02 每条带 origin**：名单里任一条目缺 `origin` 即写入被拒。[单测]
- [ ] **II-C03 缺 origin 的 legacy 不进名单**：注入一条无 origin 的 legacy 记忆，
      它不出现在任何 scope 的自动进入内容里。[集成]
- [ ] **II-C04 不推测回填**：对无 origin 的 legacy 条目，系统不按时间邻近或语义相似推测一个 origin
      并**落盘**为已验证；读取路径上允许算一个 fallback，但该 fallback 显式标 `inferred`、不写库、
      不进 evidence 图。落盘断言 + evidence 图断言各一。[集成]
- [ ] **II-C05 名单外默认不进**：名单外的住户级内容在新 scope 开工时不在上下文里。[集成]

## D. 三原语与来源

- [ ] **II-D01 import 留可读事件**：一次 import 在目标 scope 留下含来源身份、目标 scope、理由、
      `as_of`、`derived_from` 的事件，缺任一字段则该次 import 被拒。[单测]
- [ ] **II-D02 authority 不过界**：scope A 里存在「已批准部署」的记录；import 到 B 后，
      B 发起部署被拒，理由指向「授权未在本域复核」。**信息过来了，能力没过来。**[集成]
- [ ] **II-D03 裁定复述义务**：跨界进来的裁定类内容，在目标 scope 未完成复述物化
      （谁拍的、何时、拍了什么）之前，据其发起的裁定级动作被拦；复述完成后放行。[集成]
- [ ] **II-D04 promote 产物是候选**：promote 之后，住户层出现一条候选，权威 head **未**前进；
      候选带来源、`as_of`、`derived_from` 与原始证据的权威指针。[集成]
- [ ] **II-D05 回执定义完成**：做一次会被拒的 promote，回执明确为已拒绝，候选列表与权威 head 均未前进；
      做一次成功的 promote，回执明确为已提交并推进 head。拒绝、失败、跳过、仅送达四种情形
      **都不得**推进权威状态。[集成]
- [ ] **II-D06 更正走加注不走覆盖**：对一条已在住户层的记录做更正，原值字节不变，
      新增一条勘误链条目；就地覆盖的写入路径不存在。[集成]
- [ ] **II-D07 加注在读取路径上**：读取被加注对象时，加注**必然**一同返回。
      构造一条加注后只查正文，断言返回里带上了加注。[集成]
- [ ] **II-D08 删除留疤**：执行不可逆删除后，原值不可恢复，但可看见一条**不泄露原内容**的变更疤
      （疤上不得含被删内容的任何片段或可还原摘要）。[集成]
- [ ] **II-D09 转抄不洗白**：把一条 import 来的断言在 scope 内用自己的话复述后 promote，
      住户层收到的候选仍带完整 lineage（可回到 authoritative upstream），authority 不因这次复述升为一手。
      同一 assertion 完成一次 recall→generation→ingestion 后**不得**仅因自我回声获得新的独立 evidence authority。[集成]
- [ ] **II-D10 权威指针不指副本**：指针只许指权威源；拿不到权威源时显式写「本指针指向副本，权威源未知」。
      构造一个权威源不可达的场景，断言产出的是显式标注而不是一个指向摘要的指针。[集成]

## E. 身份靠 identity 不靠 role

- [ ] **II-E01 写入必带身份元组**：任何写入缺 `(source, sender_id)` 即被拒，跨界与不跨界一视同仁。[单测]
- [ ] **II-E02 role 层同形不同源可分**：定时器注入、编排注入、hook 反馈、另一 scope 的 import
      四种来源各造一条写入，四条在存储里可按来源区分；仅按 role 区分的实现本条变红。[集成]
- [ ] **II-E03 四字段分开**：`recordedAt` / `as_of` / `derived_from` / evidence 指针在 schema 里是四个字段；
      把 `recordedAt` 与 `as_of` 挤进一个 `createdAt` 的实现本条变红。[静态]
- [ ] **II-E04 控制面不住正文**：在 scope 内正文里写出一段完整的跨界指令语法（含目标 scope、理由等），
      **不产生任何跨界效果**；跨界只经 envelope 发生。正文中的寻址符号一律只是内容。[集成]
- [ ] **II-E05 人格不 promote**：把一条 scope 内的角色发言／辩论立场 promote 到住户层，
      它落地时带「局部产物」标记，且不进入住户级立场集合。[集成]

## F. 生命周期：开

- [ ] **II-F01 原子创建**：在「建 scope」「建 working folder」「住户层登记」三步分别注入失败，
      三次之后文件系统与存储里**均不残留**半个 scope 或空目录。[集成]
- [ ] **II-F02 登记失败不假装成功**：住户层登记失败时创建返回明确失败并带原因，
      scope 不进入 ready，也不接收用户输入。[集成]
- [ ] **II-F03 携带包冻结**：创建后修改主线里被带入的那条原事件的下游内容，
      隔离 scope 里的携带包内容不变（冻结截面成立）。[集成]
- [ ] **II-F04 携带包不复制授权与锁**：创建时主线持有一把锁和一份授权，
      断言新 scope 既不持有该锁也不继承该授权。[集成]
- [ ] **II-F05 摘要不替代原料**：携带包里若含摘要，该摘要带 `derived_from` 且原事件（含 eventId）同时在包里；
      只带摘要不带原事件的包本条变红。[集成]
- [ ] **II-F06 replay 明确标记**：选「从此重答」时，被选中的用户消息以**明确标记为 replay** 的形式派发，
      在事件流里可与用户新输入区分。[集成]
- [ ] **II-F07 主线不受扰**：创建期间主线原在生成的继续生成、原 ready 的继续收消息；
      主线 transcript 不被追加任何 branch 条目；住户不因 branch 动作自行开口。[集成]

## G. 生命周期：存在可知

- [ ] **II-G01 前台同步**：scope B 创建成功当刻，用户在 A 的界面（共享状态投影）即可看见 B 存在
      （名字、状态、来源）。[集成]
- [ ] **II-G02 模型侧异步且只含存在性**：A 的模型在**下一次** dispatch 收到存在信封；
      信封内容只含存在与来源，**不含 B 的任何正文**（canary 断言）。[集成]
- [ ] **II-G03 不打断不落本地**：A 正在进行的生成不被打断；A 的本地对话里不出现被追加的「B 已开」条目。[集成]

## H. 生命周期：项目型 preset（Q3）

- [ ] **II-H01 root 内默认工作**：绑定 workspace root 的 scope 里，所有具文件能力的工具默认在该 root 内工作。[集成]
- [ ] **II-H02 越界被拒并留痕**：以 `../`、绝对路径、符号链接、以及各文件 API 的其他入口尝试越界读写，
      **全部**被拒**且**留下可查的痕迹。四类入口各一例。[集成]
- [ ] **II-H03 能力清单可枚举**：系统能列出「当前有哪些工具具备文件能力」；
      **枚举不出来就不许声称文件隔离**——枚举接口缺失时，声称位必须为假。[集成]
- [ ] **II-H04 未绑目录不声称**：未绑定 workspace root 的 scope，其能力声明里文件隔离一栏
      显式为「未提供」，不是空、不是沉默。[集成]
- [ ] **II-H05 进程隔离零声称**：任何接口、文档字符串、能力声明里都不出现「进程隔离」的声称。[静态]

## I. 生命周期：关

- [ ] **II-I01 六步清单**：关闭后断言六件事同时成立——不再接新活；在途派发已处理或已取消；
      锁与占位（回合、门禁、队列席位）已释放；旧代结果被拒；局部记录已归档；
      未决候选与已发生副作用可查询。[集成]
- [ ] **II-I02 closure card 生成且住共享状态**：关闭后共享状态里出现 closure card，
      含完成状态、起止时间、产物权威指针、未收口项、副作用、送达回执六栏。[集成]
- [ ] **II-I03 closure card 不越界**：其他 scope 的 transcript 与模型上下文里**均无** closure card 内容，
      也无被自动塞入的叙事摘要。canary 断言。[集成]
- [ ] **II-I04 叙事交代需用户点头**：叙事交代在用户点「带回主线」之前只是本地候选；
      点了之后才作为候选 promote。未点时住户层查不到它。[集成]
- [ ] **II-I05 transcript 永不倒回**：不存在任何把隔离 scope 的 transcript 写入主线的代码路径。[静态]

## J. 关闭归档两份

- [ ] **II-J01 两份分开存**：关闭后存在两条独立记录——机器台账与亲笔交接信，
      两者字段不共用、不互相生成。[集成]
- [ ] **II-J02 台账不允许缺**：机器台账的六栏任一缺失则关闭流程报错。[单测]
- [ ] **II-J03 亲笔信写不出就留空**：住户未写信时，信为空且关闭仍能完成；
      **不存在**由脚本、模板或模型代写信的路径。[静态] + [集成]
- [ ] **II-J04 禁止转抄**：写信入口不接收「上一封信」作为输入；
      注入上一封信内容尝试生成新信的路径不存在。[静态]
- [ ] **II-J05 三档标注条目级**：信的 schema 校验「一条只装一档」
      （承诺与生效中的约束 ／ 事实与状态 ／ 判断与意图）。[单测]
- [ ] **II-J06 承诺档不可由继任者作废**：继任者侧标记承诺档条目作废的操作被拒，
      只能走正常解除流程。[单测]
- [ ] **II-J07 继任者不补因果**：继任者写入的记录中，不得出现对前任行为的事后原因分析
      被标为该前任的判断／意图。构造一次继任者写入，断言其 `author` 为继任者且不能挂到前代的意图档上。[集成]

## K. 生命周期：续（Q2）

- [ ] **II-K01 同身份重开**：关闭后按同一 `scopeId` 重开成功，进度可续。[集成]
- [ ] **II-K02 起新一代**：重开后 `generation` +1，`scopeId` 不变。[集成]
- [ ] **II-K03 旧代硬拒**：旧代的迟到回执被**判定不等即丢弃**并留日志，
      不是「尽量过滤」；构造一条旧代回执，断言它既未被消费也未静默消失（日志里有）。[集成]

## L. 导出与合入

- [ ] **II-L01 六字段齐全**：从 scope 导出一批记录，每条带 `scope`／可见性／来源／`as_of`／
      `derived_from`／权威指针；缺任一即该条被拒。[集成]
- [ ] **II-L02 只追加不覆盖**：导出一条与住户层已有值同标识的记录，已有值字节不变。[集成]
- [ ] **II-L03 冲突并存且标明**：上一条产生的两个值在住户层**并存**且被标为冲突，
      不静默择一。[集成]
- [ ] **II-L04 排序纪律**：同一事实的原料与衍生同时存在时，查询返回中原料排在衍生前、
      权威源排在摘要前。[单测]
- [ ] **II-L05 回执三态可分**：合入回执能区分已合入／被拒／冲突待决三态，
      三者在事件流里是三个不同值而非一个布尔。[集成]
- [ ] **II-L06 origin 三态可分**：对 legacy 记录做导出／合入，
      其 origin 显示为 `unknown` 或 `inferred`（**两者可区分**），不显示为 `verified`。[集成]

## M. 切换感知（D1，只验效果）

- [ ] **II-M01 现场变了**：从主线切到隔离 scope 时，scope 名、工作目录、带入包三项在界面上随之改变。[人工]
- [ ] **II-M02 人没变**：同一次切换中，住户身份与对话入口保持连续；
      不呈现为打开了一个新联系人或新聊天（无新会话条目产生）。[集成] + [人工]
- [ ] **II-M03 门钉在分岔那一格**：隔离 scope 内显示的时间锚是分岔时刻的 `as_of`；
      回主线时回到「现在」而不是分岔口。[人工]

## N. 反向样本与阈值纪律

- [ ] **II-N01 反向样本必跑**：读入侧任何自动过滤器上线前，用一组**本应放行**的样本
      （含安全类记忆）跑一遍，误杀率作为验收项**记录在案**。闸误杀比噪音贵一个量级。[集成]
- [ ] **II-N02 v0 无自动跨界**：代码中不存在任何依据出现次数、相关度、时间间隔或其他阈值
      **自动**触发跨界的路径；配置里也不存在这样的阈值项。[静态]
- [ ] **II-N03 未声称的不许出现在文案里**：能力声明、错误信息与用户可见文案中，
      不出现本轮未验收的隔离声称（进程隔离、非项目型 preset、主题召回）。[静态]

## 灯的纪律

- 图纸获批**不勾灯**。本清单的每一盏都要由实现单跑出来的证据点亮。
- 本清单不借用其他套件的绿灯。C5 证明的是不串房，不是不串 scope。
- 「实证」二字只给本清单跑出来的东西用；楼里的读数在跑出来之前不叫项目实证。
- 标 [人工] 的三条勾的时候必须写下看的是什么（截图、录屏或逐步描述），
  只写「看过了」不算。

## 与 #157 群聊清单的接缝

两套清单各自独立点灯，但有三处语义必须一致，实现时若发现不一致以**先落地的一方**为准并回补另一方：

| 语义 | 本清单 | 群聊清单 |
|---|---|---|
| 「到达注意力」不等于「进入长期记忆」 | II-B02 / II-D04 | GC 侧「听见 ≠ 记账」相关灯 |
| 一条内容在不同账上的状态不得压成一个布尔 | II-L05 / II-I01 | GC 侧三本账相关灯 |
| 目标域在动作当刻声明，不靠事后过滤 | II-D01 / II-E04 | GC 侧载荷显式声明相关灯 |

**字段冲突预警**：群聊的「房间」是多住户共享的可见性容器，本单的 `scope` 是单住户内的策略边界。
两边若都用 `scopeId` 命名，必须能区分——否则一次群发会被判成一次跨 scope import。
