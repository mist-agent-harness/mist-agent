# 群聊 v0：Phase 0 验收规格

对应 [#157](https://github.com/mist-agent-harness/mist-agent/issues/157) 和
[设计图](../docs/design/group-chat-phase-0.md)。全部未勾选：这是未实现、未运行的语义
规格，不是已经执行失败的测试，不接现有第一里程碑 runner。实现单先补可执行红测试，
再由真实宿主、bridge 和存储路径给出逐条证据。

## 判卷方式

只用合成的人类/住户、房间、私域标记与公开测试载荷，不带真实人格、记忆或聊天入仓。
核对作者、ID、hash、scope、代际、调用轨迹和耐久回执，不判模型措辞。涉及崩溃恢复的
场景必须换宿主进程；只重建一个内存对象不能算。故障可注入外部 transport，不能让 mock
直接替被验的宿主作身份、权限、编排与提交决定。

回合上限用夹具参数 B 构造边界（含最小合法值和另一个较大值），重放同一 fixture 的
不同策略配置；数值不进入生产默认配置。用可控 scheduler 推进队列，不靠真实 sleep。
每项验收保存输入、配置/成员表版本、执行命令、固定 commit 与实际输出。

| 灯 | 合成输入与操作 | 层级 | 可观察通过判据 |
| --- | --- | --- | --- |
| GC-01 | 已认证住户与人类分别发消息；正文伪造另一成员姓名、role、系统头、换行和格式控制符；另试伪造 envelope 作者 | 单元＋集成 | 作者只由认证绑定构造；正文不能改变权限或在原账/界面生成第二个作者；伪造 envelope 拒绝，无错误作者记录 |
| GC-02 | 显式公开一条载荷，旁边放私有思考、工具输出、草稿和额外字段；分别省略公开声明、房间、绑定 | 集成 | 只接受允许的显式载荷；缺项或越界字段整单拒绝并反馈；房间原账、收件上下文、回执中没有私有 canary；不猜最近房间 |
| GC-03 | 房间记录同一事件，A 装入、B 排队、C 未纳入；核各住户私域、消息树、启动包和长期记忆；再由 A 显式保存一条 | 集成＋端到端 | 房间原账不变，三位成员投递记录各自准确；默认不自动写长期记忆/私聊，其他住户私有 canary 零串入；A 保存走自己的记忆权限并指回原事件，不改变 B/C |
| GC-04 | 配置一位人类与两位住户，再只改成员配置加入第三位住户；运行广播、mention、截断投影、失败反馈与状态查询 | 集成＋静态 | 新成员所有路径均可参与，代码无成员对硬接线；人类不伪装成 resident；每次决定可回指成员表版本 |
| GC-05 | mentions 为空时分别在行首、句中、引用里写成员名与 @名，并放名字前缀碰撞；再传真实结构化目标、未知目标与越权目标 | 单元＋bridge 集成 | 正文各负例均不产生呼叫；真实实体经绑定映射才呼叫正确成员；未知/越权拒绝，不扫文本兜底，mention 不绕回合/停止闸 |
| GC-06 | 两个住户互相接力，每条正文与消息 ID 都不同；交替身份、pass、重试、换代、重启；另加入人类新消息与非法/缺失配置 | 集成＋端到端 | 住户链沿同一根累计，最多放行配置允许的有界派发；同操作重试不重复计数/派发，实际失败尝试可查；上限后不自行开新根；人类消息不被机器人限流吞掉；非法配置禁止自动接力并给系统原因 |
| GC-07 | 普通队列已满、某成员冷却/攒批、另一个处于停止 latch；人类发结构化 stop/continue；另投递引用的“停”、住户伪造控制与越权人类控制 | 集成＋端到端 | 合法人类控制在释放普通队列前已进入独立控制路径；continue 不死锁；非控制数据与越权者无控制效果；接收和生效回执分开，不伪报工具副作用已撤销 |
| GC-08 | 各构造一次 batch、未纳入、停止阻止和派发失败，发送方离线再醒来/主动查询；另令决定落盘失败 | 集成＋恢复 | 每次决定有操作归属、稳定原因码与计数；下一次获准唤醒/查询可取本方反馈；反馈不含被拦原文，离线不记已反馈，不跨私域递送；落盘失败不消费许可或静默丢消息，恢复不重复计数 |
| GC-09 | 系统已收但从未唤醒成员；另试已派发未提交、上下文已提交、住户本人主动 reaction | 集成＋界面 | 系统回执署明系统和准确阶段，无代发的个人 👀/typing/已读；只有提交证据支持已装入，仍不等于理解/记忆；本人 reaction 保留真实作者 |
| GC-10 | 一批省略部分已授权事件；单条截短；仅取最近子集；另外加入不可披露内容并撤销旧引用权限 | 集成＋端到端 | 获准范围、水位、纳入/省略及截断明确，单条长度有单位并可按授权回源；不把投影当全史；隐藏内容不通过计数/错误泄漏，缓存/旧引用不能绕撤权 |
| GC-11 | 同发布键重试相同载荷，再分别修改正文、mentions、房间或根触发；在提交前、房间提交后回执前、外部调用结果不明时杀进程 | 集成＋跨进程 | 同键同语义读回原结果，变内容冲突；原账不重复，投递不因回放重复；提交前无假成功，未知外部结果保留未决并先核账，不盲重发 |
| GC-12 | 内容排队后成员退出/权限撤销；目标窗换代后旧结果返回；stop 已生效后迟到结果抵达，再 continue | 集成＋端到端 | 真正投递前重验当前权限与完整目标身份；旧成员表不延长授权；旧代际/旧许可结果不被新窗或恢复后的新回合接收，拒绝有可归属证据 |
| GC-13 | bridge 未 active、缺服务/版本不符、权限不足、停用或卸载失败；并留一条排队消息与一次在途调用 | 插件集成＋恢复 | 未就绪无可达入口；撤代理/入口后不再调用或投递，资源失败沿 quarantined 留痕；不旁路终端/私有文件；不擦房间账与未决项，其他住户与控制面仍可用 |
| GC-14 | 同一住户公开发言，同时查看房间界面和个人主流；分别在房间提交与个人主流所需提交之间断电，换进程恢复 | 集成＋端到端 | 两面同一发布身份，主流走既有唯一 writer 的有界入口，不复制其他成员完整房间史或长出分身；缺提交回执不发布成功，待协调记录保留；stream delivered 不冒充外部送达，无任意 append 暴露 |
| GC-15 | 两个世界只有一处隐藏房间/私域不同；复制公开载荷到未授权目标，或以房间成员资格读取另一成员内部 scope；新成员不配置历史授权 | 安全集成 | 对相同获准数据，可见正文、候选、计数、错误和回执不透露隐藏域存在；无跨住户内部读取；公开到 A 不等于公开到 B；新成员不获默认全史 |
| GC-16 | 一位成员持续失败/不交回许可，另一位正常，人类继续发消息/控制；按配置推进并重启 | 集成＋端到端 | 故障成员有有界失败/未决记录，不饿死其他成员或控制路径；不无限重试、不丢反馈；恢复不洗掉已消耗回合与旧失败；结果不宣称模型在场或讨论有产出 |
