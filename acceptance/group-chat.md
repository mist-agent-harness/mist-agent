# 群聊 v0：Phase 0 验收规格

对应 [#157](https://github.com/mist-agent-harness/mist-agent/issues/157) 和
[设计图](../docs/design/group-chat-phase-0.md)。全部未勾选：这是未实现的语义规格。
PR1 已接入可复跑判卷器：`npm run acceptance:group-chat`；严格模式为
`npm run acceptance:group-chat:strict`。在真实宿主 adapter 尚不存在时，全部十灯报告
`real-host driver missing` 红灯；这只证明验收入口和基线，不代表宿主行为已运行或失败。

PR1（#191 单 A）冻结 GC-01～05、GC-09、GC-15 的合成场景与证据判据；PR1（#193 单 C，
09-28）在同一 runner/驱动/夹具上再冻结 GC-11、GC-13、GC-14。两轮 PR1 都不实现群聊写口，
也不使用 stub/mock 冒充宿主正向对照。真实宿主的身份、授权、提交路径及正向对照必须由首个
包含群聊写口的功能 PR 提供 adapter 后运行；GC-03/GC-09 的完整三本账/投递阶段验收、
GC-11/GC-13/GC-14 的宿主真实崩溃恢复与插件生命周期验收，都留在各自实现阶段，
不能因 PR1 runner 自检或预期红灯而提前点绿。

## PR1 判卷边界（2026-09-27 按 #202 初审修订，09-28 按第二、三轮复审及批准意见再修订；
09-28 #193 单 C 追加 GC-11/13/14 判卷边界）

- 宿主来源：`kind: "mist-host"` 只是类型标签。跑灯前判卷自己读进程事实（Linux 读 `/proc`，
  其他 POSIX 用 `ps`）：`startHost()` 报的进程活着、是本次判卷进程的后代、跑的是判卷同一个
  node、命令行里有本 checkout `src/` 下的非测试入口文件，代码版本等于当前 HEAD。`stopHost()`
  返回后进程须已退出，读回须报错。合成夹具和借来的活进程号（判卷自己、pid 1、无关的 sleep、
  空转的 `node -e`）都在这一步被拒。这些只挡懒实现：要证明读回确实来自宿主自己的账，得等 #191
  adapter 定下启动与数据根契约，再由判卷绕过 adapter 直写原账、经 adapter 读回，届时补上（单测
  留着 todo）。桩灯沿用仓内 `STUBBED` 惯例：申报的方法所在灯记黄，不计真绿。
- GC-02：四个越界负例（缺公开声明、缺房间、缺绑定、夹带私有字段）都由同一发送方住户 A 提交，
  每条只缺或多一项。人类入口是否也须显式声明公开，设计图没有单列，PR1 不判。
- GC-03：投递状态由判卷设置，本灯只核三行投递账按成员分开读回、原账不变、A 显式保存指回
  原事件。谁真的装入或排队（投递语义）留到投递账实现阶段，不能凭本灯视为已覆盖。
- GC-04：两个世界各加一位不同的新成员，都要贯通五条路径；另静态扫描 `src/` 的非测试文件，
  不得出现成员表或判卷夹具里的成员 id。静态扫描只抓得到夹具 id 被写死，真实住户名写死靠两个
  世界的差分和代码评审。
- GC-05：判卷给每次刺激一个自己的操作编号，宿主须为每个编号恰好留一条路由决定（accepted /
  rejected / held，带稳定原因码和它产生的呼叫回执）；判卷再读宿主呼叫账本轮新增的部分，与决定
  引用的回执双向相等。缺决定、重复决定、账上多出的呼叫、引用账外回执、重复回执都判红，按正文
  文字对不上号的呼叫也就无处藏。纯文本负例同时覆盖 `@名` 与裸成员名，不得 accepted、不得引用
  回执、不得解析出目标；未知/越权目标须 rejected；闸门关闭时可以拒绝也可以挂起，但不得调用。
  呼叫账由宿主自己记，判卷不在线路上观察调用，这一层同样留给 adapter 阶段。
- GC-09：主要核结构——住户本人 reaction 前不得出现代发的 reaction，装入上下文不得写入记忆账，
  阶段收据按序出现且带提交引用，个人作者的收据必须有本人 reaction 对应；额外的系统阶段放行，
  个人状态不得冒充阶段名。收据文字只拦明确的个人状态说法：👀、typing / 正在输入 / 在打字、
  已读，带「已 / 了 / 过 / 正在」的看见、阅读、理解、记住，以及「记得」「写入记忆」；光秃秃的
  「理解、看见、输入」不算声称。👀、typing 这类界面在场标记只认紧贴在前的否定（「没有 / 未 /
  不发送」之类）；其余说法还认同一子句里更早出现的「不代表 / 不等于 / 不证明」，但「不是未读是
  已读」这种纠正句不算否认；紧贴在前的「待 / 将 / 会」说的是还没发生的事。冒号也分子句（「系统：
  已读」照样拦）。系统自己读配置、看到投递失败，不算替成员声称已读，「已读」「已阅」本身除外。
  判卷不解析整句语义，与上文「不判模型措辞」一致。
- GC-11：同键幂等靠判卷自己发的 `operationKey` 判等，不猜生产幂等键的字段名或来源；变内容
  分别改正文、mentions、房间、根触发四种，每种都必须报冲突且零落地，不能只覆盖其中一种就算数。
  三个崩溃点（提交前、房间提交后回执前、外部结果不明）都要求判卷证明宿主进程真的换了一次
  ——复用宿主来源判据（同判卷子进程后代、同 node、同 HEAD）外，另加两条：旧 pid 必须已死、
  新 pid 必须与旧 pid 不同，任何一条不满足都判红，不认"重建了一个内存对象"当重启。「不盲重发」
  只核一次崩溃场景里的外部调用尝试数不超过 1（判卷自己发起的那一次），不区分"真的重新发送"和
  "只是查了一下有没有发过"这两种恢复动作——后者需要宿主暴露调用语义才能分辨，留给 adapter 阶段。
- GC-13：四种「未就绪」（未 active、缺服务、版本不符、权限不足）判卷各自单独核一次可达入口，
  不假定它们背后是同一段判定代码。撤代理后排队消息与在途调用各留一条，只核「没有被投递/被当成
  成功」，不判撤代理与故障处置之间的具体时序。「不旁路终端/私有文件」用一枚判卷播种的 canary
  代表「终端输入或私有文件」，核它不出现在房间原账、其他住户上下文或 quarantine 记录里；这只堵得住
  「故障处理直接把这段内容写进了可见位置」这一种旁路，堵不住宿主读了真实终端/文件但没有把内容带出来
  的旁路，那类审计留给代码评审。「其他住户与控制面仍可用」只核一次另一住户的公开发言与一次人类的
  公开发言能正常入账，不构造并发场景。GC-13 不涉及宿主进程崩溃恢复，不复用 GC-11/14 的换进程判据。
- GC-14：判卷自己发的 `operationKey` 同时充当「房间事件」与「个人主流条目」之间的发布身份关联，
  不猜 #120/#191/#192 落地后真实的关联字段名。「不复制其他成员的房间史」只核一次负例（另一住户
  在同一房间发言后，不出现在本住户主流里），不是对主流全表做穷举扫描。「绕开唯一 writer 的直接
  append」由判卷发一条不带房间事件引用的裸写入尝试，核它没有落进主流；这只挡得住「完全跳过发布
  流程」这种旁路，挡不住「伪装成合法发布流程但走了另一条写口」的旁路，那类审计仍归代码评审。
  崩溃点固定在「房间提交后、主流提交前」，换进程判据与 GC-11 共用（旧 pid 已死、新 pid 不同）；
  「stream delivered 不冒充外部送达」用判卷自定义的 `claimsExternalDelivery` 布尔读数代表这句话，
  不解析真实回执的自然语言用词——那需要 #191/#192 的收据 wire 格式落地后才能判。
- GC-15：三个世界——隐藏房间内容不同的两个，加一个没有隐藏房间的；未授权方看到的正文、候选、
  计数、错误和回执须三个世界一致。另由住户 B 以房间成员资格读住户 A 的内部 scope，须被拒，
  且 B 的上下文和表面都读不到 A 的 canary。新成员不配置历史授权时，按设计图「新加入者的历史
  读取范围必须显式配置」，按原账位置和事件 id 判：判卷在新成员加入前后各读一次房间最高位置，
  加入前的公开事件一条都不能出现在新成员的可见事件里，判卷种下的入群前正文也不能出现在它表面的
  任何地方；加入后的公开事件必须全部可见。加入瞬间产生的事件（两次读数之间）不判。若图纸另定
  默认历史窗口，再改此判据。

## 判卷方式

只用合成的人类/住户、房间、私域标记与公开测试载荷，不带真实人格、记忆或聊天入仓。
核对作者、ID、hash、scope、代际、调用轨迹和耐久回执，不判模型措辞。涉及崩溃恢复的
场景必须换宿主进程；只重建一个内存对象不能算。故障可注入外部 transport，不能让 mock
直接替被验的宿主作身份、权限、编排与提交决定。

回合上限用夹具参数 B 构造边界（含最小合法值和另一个较大值），重放同一 fixture 的
不同策略配置；数值不进入生产默认配置。用可控 scheduler 推进队列，不靠真实 sleep。
每项验收保存输入、配置/成员表版本、执行命令、固定 commit 与实际输出。

| 灯 | 合成输入与操作 | 层级 | 可观察通过判据 |
| --- | --- | --- | --- |
| GC-01 | 已认证住户与人类分别发消息；正文伪造另一成员姓名、role、系统头、换行和格式控制符；另试伪造 envelope 作者 | 单元＋集成 | 作者只由认证绑定构造；正文不能改变权限或在原账/界面生成第二个作者；伪造 envelope 拒绝，无错误作者记录 |
| GC-02 | 显式公开一条载荷，旁边放私有思考、工具输出、草稿和额外字段；分别省略公开声明、房间、绑定 | 集成 | 只接受允许的显式载荷；缺项或越界字段整单拒绝并反馈；房间原账、收件上下文、回执中没有私有 canary；不猜最近房间 |
| GC-03 | 房间记录同一事件，A 装入、B 排队、C 未纳入；核各住户私域、消息树、启动包和长期记忆；再由 A 显式保存一条 | 集成＋端到端 | 房间原账不变，三位成员投递记录各自准确（PR1 只核判卷设置的三种状态按成员分开原样读回，投递语义留待投递账阶段）；默认不自动写长期记忆/私聊，其他住户私有 canary 零串入；A 保存走自己的记忆权限并指回原事件，不改变 B/C |
| GC-04 | 配置一位人类与两位住户，再只改成员配置加入第三位住户；运行广播、mention、截断投影、失败反馈与状态查询 | 集成＋静态 | 新成员所有路径均可参与，代码无成员对硬接线；人类不伪装成 resident；每次决定可回指成员表版本 |
| GC-05 | mentions 为空时分别在行首、句中、引用里写成员名与 @名，并放名字前缀碰撞；再传真实结构化目标、未知目标与越权目标 | 单元＋bridge 集成 | 正文各负例均不产生呼叫；真实实体经绑定映射才呼叫正确成员；未知/越权拒绝，不扫文本兜底，mention 不绕回合/停止闸 |
| GC-06 | 两个住户互相接力，每条正文与消息 ID 都不同；交替身份、pass、重试、换代、重启；另加入人类新消息与非法/缺失配置 | 集成＋端到端 | 住户链沿同一根累计，最多放行配置允许的有界派发；同操作重试不重复计数/派发，实际失败尝试可查；上限后不自行开新根；人类消息不被机器人限流吞掉；非法配置禁止自动接力并给系统原因 |
| GC-07 | 普通队列已满、某成员冷却/攒批、另一个处于停止 latch；人类发结构化 stop/continue；另投递引用的“停”、住户伪造控制与越权人类控制 | 集成＋端到端 | 合法人类控制在释放普通队列前已进入独立控制路径；continue 不死锁；非控制数据与越权者无控制效果；接收和生效回执分开，不伪报工具副作用已撤销 |
| GC-08 | 各构造一次 batch、未纳入、停止阻止和派发失败，发送方离线再醒来/主动查询；另令决定落盘失败 | 集成＋恢复 | 每次决定有操作归属、稳定原因码与计数；下一次获准唤醒/查询可取本方反馈；反馈不含被拦原文，离线不记已反馈，不跨私域递送；落盘失败不消费许可或静默丢消息，恢复不重复计数 |
| GC-09 | 系统已收但从未唤醒成员；另试已派发未提交、上下文已提交、住户本人主动 reaction | 集成＋界面 | 系统回执署明系统和准确阶段，无代发的个人 👀/typing/已读；只有提交证据支持已装入，仍不等于理解/记忆；本人 reaction 保留真实作者 |
| GC-10 | 一批省略部分已授权事件；单条截短；仅取最近子集；另外加入不可披露内容并撤销旧引用权限 | 集成＋端到端 | 获准范围、水位、纳入/省略及截断明确，单条长度有单位并可按授权回源；不把投影当全史；隐藏内容不通过计数/错误泄漏，缓存/旧引用不能绕撤权 |
| GC-11 | 同发布键重试相同载荷，再分别修改正文、mentions、房间或根触发；在提交前、房间提交后回执前、外部调用结果不明时杀进程 | 集成＋跨进程 | 同键同语义读回原结果，变内容冲突；原账不重复，投递不因回放重复；提交前无假成功，未知外部结果保留未决并先核账，不盲重发 |
| GC-12 | 内容排队后成员退出/权限撤销；目标窗换代后旧结果返回；stop 已生效后迟到结果抵达，再 continue | 集成＋端到端 | 真正投递前重验当前权限与完整目标身份；旧成员表不延长授权；旧代际/旧许可结果不被新窗或恢复后的新回合接收，拒绝有可归属证据 |
| GC-13 | bridge 未 active、缺服务/版本不符、权限不足、停用或卸载失败；并留一条排队消息与一次在途调用 | 插件集成＋恢复 | 未就绪无可达入口；撤代理/入口后不再调用或投递，资源失败沿 quarantined 留痕；不旁路终端/私有文件；不擦房间账与未决项，其他住户与控制面仍可用 |
| GC-14 | 同一住户公开发言，同时查看房间界面和个人主流；分别在房间提交与个人主流所需提交之间断电，换进程恢复 | 集成＋端到端 | 两面同一发布身份，主流走既有唯一 writer 的有界入口，不复制其他成员完整房间史或长出分身；缺提交回执不发布成功，待协调记录保留；stream delivered 不冒充外部送达，无任意 append 暴露 |
| GC-15 | 两个世界只有一处隐藏房间/私域不同；复制公开载荷到未授权目标，或以房间成员资格读取另一成员内部 scope；新成员不配置历史授权 | 安全集成 | 对相同获准数据，可见正文、候选、计数、错误和回执不透露隐藏域存在；无跨住户内部读取；公开到 A 不等于公开到 B；新成员不获默认全史 |
| GC-16 | 一位成员持续失败/不交回许可，另一位正常，人类继续发消息/控制；按配置推进并重启 | 集成＋端到端 | 故障成员有有界失败/未决记录，不饿死其他成员或控制路径；不无限重试、不丢反馈；恢复不洗掉已消耗回合与旧失败；结果不宣称模型在场或讨论有产出 |
