# 验收清单：生产 MistWindowHistoryPort 持久化（对应 issue #120）

判卷先行：本清单全未点亮进仓，实现完成的标准是逐条可勾。
本页只钉行为与证据，不替 #84 决定 schema、字段名或端点名；下面出现的
`eventId`、`streamSeq` 都表示 #84 已拍板的语义把手，最终拼写随其第一刀落地后对齐。

认领口径（#120 楼内，issuecomment-5447844494；先决①于 2026-08-29 经 #120
楼里当面确认——望舒主笔授意批字认可「一份」，issuecomment-5461040293）：
**一份底座**——canonical stream event store 是唯一底座与唯一写方；window
history 是它按 `(windowId, generation)` 的只读 projection，不构成第二条写入
路径。「分开逻辑流」只到视图层——list 摘要与 history 分页可以分开渲染；Clare
的「共用物理底座、分开逻辑流」随批驳回。本选边已是楼里裁定，作判红依据。

## 判卷边界

- **port 只读**：判卷对象是 projection 与底座之间的契约——summarize/read 的行为、
  故障语义、跨进程持久性。canonical stream 自身的 writer、eventId、streamSeq 语义
  归 #84 的 OS-01/02 判，本页不重判、不另造第二套成功语义。
- **一份底座**：任何让 window history 自带写入路径、或维护第二份需要裁定权威的
  数据的实现，直接判红，不进入逐条判卷。（先决①批字见上「认领口径」段。）
- **只判可核事实**：比较字节、序号、hash、结构化错误与真实副作用；不判
  「看起来像有历史」。读不到与读到是空必须机器可分。

代价：projection 不自带写入路径意味着 #84 未落地前本单无法点灯，排期被上游锁死；
fail-closed 会把一部分「其实没事」的读取故障显式报红，增加误报处理成本；格式版本
字段与墓碑让每一条记录为未必发生的迁移付钱；「一份」裁定下 history 投影主流与
OS-03/04「局部 transcript 不入主流、归档流水只进证据面」的并存语义，留待施工时
交代清楚，不在清单里含糊。这些是「history 不活在内存里」的代价。

## 六盏灯

每条带主证据形式。标 [集成] 的由 Vitest 集成测试提供（真实宿主子进程、真实文件
系统目录，杀得起拉得起，可注入故障）；标 [静态] 的由代码检索与类型检查提供。

- [ ] **WH-01 跨进程重启可读** [集成]：向底座写入若干窗事件后杀死宿主进程，新进程
  起来经 port `read` 取回同一窗的历史：事件集合、顺序与不可变 payload 的内容 hash
  与死前逐项等价；分页语义（`beforeSeq` / `maxMessages`）重启前后一致。
  只在单进程内存里成立的实现判红。

- [ ] **WH-02 并发按窗隔离，冲突有判据** [集成]：冲突域按稳定 `windowId` 隔离；
  同一窗的写经唯一 gateway 串行，`seq` 由底座 store 发号；写请求携带
  `generation`，旧代迟到写 fail-closed 拒绝、拒绝事实机器可见；换气
  （generation+1）不换 writer。并发到达同一窗的两个合法写，projection 复读
  结果与 store 发号顺序逐项一致；被拒的冲突写（旧代迟到写、同一幂等把手换
  内容重试）在 projection 侧如实呈现为缺席，不得被补全、重排或静默改写。
  底座定序语义与 OS-01/02 重叠处共用断言来源，不另造第二套；但本条判的是
  本单自己的冲突判据，不以 OS-01/02 判绿代替本灯。

- [ ] **WH-03 换气前后引用不悬空** [集成]（与 MV-D10 同族，共用断言来源）：换气
  `generation + 1` 前后，`windowId` 逐字不变；换气前按 `(windowId, generation)`
  取得的 history 引用在换气后仍解析到同一批事件，归档窗可读。**判红样例**：换气后
  旧引用返回空页且被当作「一切正常」；或 projection 在换代后丢失对上一代事件的
  寻址能力。**寻址口径**：默认按稳定 `windowId` 读整窗只读流水，事件自带
  `generation` 或换代边界；`(windowId, generation)` 是持久化 provenance，不是
  线协议主键——现行 `session.history` 与 `MistWindowHistoryRef`
  （`residentId/windowId/headId/archived`）均无 `generation` 字段。

- [ ] **WH-04 读不到 fail-closed** [集成]（#96 双前像判据）：注入存储读失败与
  数据缺失两种故障，`summarize` / `read` 必须返回结构化错误，不得返回空页冒充
  「这窗没有历史」。「读不到」与「读到是空」不得编码成同一值；只有日志字段、
  调用方拿到正常空结果，判红。**部分损坏单判**（chaodeng060 补灯建议，
  2026-08-29）：一页中个别条目 payload 损坏（hash 不符 / 无法解码）时，不得
  降级为「少几条的正常页」静默丢数据——损坏的存在必须在返回值层面机器可见；
  只在日志里记录而调用方拿到的页与正常页不可分，判红。

- [ ] **WH-05 迁移可回滚** [集成]：v1 格式记录经一次模拟格式演进（v1→v2）后，
  迁移可退回 v1，退回后逐条记录与迁移前字节等价，port 读数不变。被 v2 取代的
  旧信号点留有显式墓碑记录，不是无声消失；墓碑本身可经 port 或证据面读到。
  **迁移中断态单判**（chaodeng060 补灯建议，2026-08-29）：迁移进行到一半宿主
  被杀（或盘满）后重启，存储必须要么可识别为「迁移未完成」且可续跑或整体退回，
  要么迁移本身原子；重启后 port 读出 v1/v2 混合页而被当作正常数据，判红。

- [ ] **WH-06 写入路径唯一** [静态]：`MistWindowHistoryPort` 类型上无写入口
  （`summarize`/`read` 之外无方法）；生产组装中只有唯一写方（canonical stream
  writer，先决①已定）持有底座的写句柄；全局检索发现第二条写入 window-event
  记录的路径，本条判红。

## 变绿条件

本页合入只代表判卷程序已写清，六盏默认保持未勾。点灯必须给出真实存储证据
（真实目录下的落盘文件，非内存替身）与故障注入证据；用 mock 直接返回期望对象
不足以点灯。桩的使用按第一里程碑 README 的规矩申报 `STUBBED`，桩灯不计绿，
隐瞒申报按伪证论。与 MV-D10、#84 OS-01/02 已有判据重叠的地方共用断言来源，
不复制一套日后会漂移的语义。
