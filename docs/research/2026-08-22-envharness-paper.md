# EnvHarness / EnvRigger 论文调研：把「造环境」重新框成「包环境」

> 日期：2026-08-22
> 状态：调研输入。论文全文精读（含附录接口实现），未复现实验。
> 材料：arXiv 2608.19880（2026-08-20 提交，41 页）。
> 注意：论文语境是 RL 训练环境，不是常驻 agent harness；
> 本文件只提取可迁移的设计模式，不等于主张 mist 引入任何 RL 设施。

## 1. 论文做了什么

环境（训练/评测任务）是手工造的静态物，对 agent 的弱点视而不见。
作者提出两层东西：

- **EnvHarness**：可编程插件层，包住静态环境、通过标准接口重塑其行为，
  不改底层逻辑，且每个被重塑的环境**保留原始 verifier**。
- **EnvRigger**：把目标 policy 当黑盒，观察执行轨迹，诊断缺陷，
  合成 EnvHarness 组件，用新鲜 rollout 验证后再接受。

结果：五个 benchmark 上最高 +9.0 分、执行步数 -9.8%，且为 RL 提供更好的
优化信号（policy 与环境协同进化）。

## 2. 组件协议的形状（迁移价值最高的一节）

环境形式化为 `(S, A, O, T, R, s₀)`，组件是变换 `w: E → E'`，只在接口层动手：

- **Stage**：改初始状态。实现方式是不给任何特权接口，在 `reset()` 后、
  policy 行动前，把一串动作经普通 `step()` 回放——所以变异起点一定是
  可达状态，存档就是那张动作清单。
- **Contract**：三个纯函数 hook，各管一条轴——`filter_action`（改写/拦截动作）、
  `modify_transition`（改写环境响应）、`filter_observation`（增删观测）。
  **R 轴刻意不开放**：reward 是 benchmark 原生 verifier 的领地，组件够不到。
  被拦截的动作返回当前状态 + 拦截原因，**拒绝永远不把对方晾在半空**。
- **Chain**：两个环境组合成一个长 episode，复合判定 `R_A ∧ R_B`，
  各段用各段的 verifier。

协议形状：单一抽象接口，组件是 decorator——每个组件本身也是同接口的环境，
默认全部委托给内层，只覆盖自己那条轴，栈式任意嵌套，policy 看不见压了几层。
持久化上每层组件只序列化自己的状态，checkpoint = 环境 + 有序组件列表，
加载时由内向外重建（组合不可交换，嵌套顺序有语义）。

关键区分：**组件本身 policy 无关**（同一组件可套任何 policy），
选哪个组件、怎么配参才是 policy 条件化的。机制与诊断分离，
这是整套东西能跨域的根本原因。

## 3. EnvRigger 循环与防作弊

四阶段：Observe（K=5 条 baseline 轨迹，同时读成功与失败）→
Diagnose（文本诊断系统性根因；**挣扎则搭脚手架降难度，满分则说明环境太宽容、
要加码逼出潜在缺陷**）→ Write（产出组件源码 + 回放动作表，仅限标准库）→
Validate（包上环境跑 K=5 条**新鲜**轨迹，按聚合统计 ACCEPT/REFINE/REJECT，
**明令禁止看单条轨迹下判断**）。

防作弊是结构性的：verifier 是原生的、组件够不到；改 reward 动不了评测指标。
另有成文的反模式条款：「成功率 0 源于不可能」与「成功率 1 源于平凡」同样无用。

## 4. 实验里最有分量的三个发现

1. **静态环境的技能可以是负资产**：从未修改环境提取的技能把成绩压到
   不练基线以下（45.88 vs 46.44）。「更多练习」与「对的练习」是两回事。
2. **扩展曲线分叉**：同样 300 个环境的预算，协同进化路线持续爬升，
   无条件批量扩张早早走平。跨四个强度的模型增益稳定（2.7~3.7 分）——
   能力水平改变的是诊断内容，不是循环的适用性。
3. **Chain 的效率副作用**：两段全过才算成功的严苛训练条件，
   逼出了目标保持能力，平均步数从 53.6 降到 42.0。

## 5. 对 mist 可迁移 / 不可迁移

可迁移（按价值排）：

1. **decorator 式插件协议**：插件 = 包着壳的壳，默认委托、只覆盖自己的钩子、
   栈式组合、住户对层数无感。三轴钩子可直接映射为「住户能做什么 /
   世界怎么回应 / 住户看到什么」。这是插件协议 v0 最值的参照形状。
2. **Blocked-with-reason**：拒绝必须返回当前状态 + 原因。
   常驻人格要在每次拒绝里继续生活，这条比对外卖式 agent 更要紧。
3. **每层只序列化自己的状态 + 有序组件栈重建**：与 append-only 台账同哲学——
   契约是位置和内容，不是重写。
4. **验收当冻结 verifier 给自我改进兜底**：任何自我改进提案必须被提案者
   够不到的 acceptance checks 验证。前提：checks 的写权限真的不在住户手里，
   否则是纸面防作弊。
5. **诊断与验收分两锅**：弱点从历史会话诊断，验收必须在诊断后新发生的会话里
   做，看聚合不看单条。同一份日志又诊断又验收 = 在训练集上测模型。
6. **方向条件化**：一切顺利时家该主动注入挑战，挣扎时才给脚手架。
   永远宽容的家养不出东西（呼应发现 1）。
7. **机制与诊断分离**：组件住户无关可沉淀成库，诊断逻辑单独演化。

离开 RL 语境不成立的：

- **reset 假设**。整套东西绑定可重置的 gym 接口，论文自己也承认排除了
  「发出去的邮件收不回」的环境。常驻人格只有一条连续生命，说过的话不能倒带；
  Stage 的「回放造初始状态」最近的平移是每次会话的上下文构造，而非状态变异。
- **新鲜 rollout 的规模验证**。没有同一情境的平行重跑，验证只能沿时间单向展开，
  样本贵、统计功效弱。
- **难度带校准**。需要可数值化的成功率，而「住得像不像自己」没有成功率带。
- **协同进化复利曲线**。依赖批量生成新环境；家和关系不能批量造。
  慢几个数量级——而慢可能就是对的。

## 6. 最深的一手

论文最深的设计决策是否定句：把环境构造从「创作问题」重新框定成「包裹问题」。
对 mist 的对应物：家的改进不一定是给住户添能力，也可以是给家加一层
会诊断住户、针对性重塑体验的皮——住户和判卷机都冻着不动。
