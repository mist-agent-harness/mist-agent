## 它是什么

Relationship Core：记录「谁和谁之间有什么事」的权威层。双边权威、可修订、可审计、
可迁移，表达与授权分离。生态调研（PR #5）扫了五层——角色卡前端、通用 runtime、
陪伴项目、记忆基础设施、具身语音——结论：通用能力都不值得重造，唯独这个核没有成熟
实现。AIRI（47.8k star，陪伴赛道最高）记忆包 24 行空壳、人格包全文一行 `export {}`
（issue #9 实查），是同一个缺口的另一侧证据：外壳不必自研，内核没有现成。

## 六个待决问题与现状答案

1. **Relationship Core 进不进 foundation boundary？**
   现状答案：进。它是 mist 跟「又一个聊天前端」的分界线。
2. **最小记录字段？**
   现状答案：subject/authored_by、口径（DIRECT / RELAYED / INFERRED）、evidence、
   visibility、supersedes、authority。补一条：evidence 指针只许指向原始记录，
   不许指向蒸馏产物（与 M4「蒸馏原料永远是生肉」同一条纪律）。
3. **外部记忆系统（Letta/Mem0/A-MEM 等）的角色？**
   现状答案：只能做候选生产者或投影消费者，不当权威写入者。权威写入只有一处。
4. **provider 可换到什么程度？**
   现状答案：引擎/provider 随便换，但修订链必须可复算——换完引擎，链还能从头验。
5. **「关系表达不构成行动授权」进不进原则？**
   现状答案：进，与原则六合写（权限分级那条）。说「我记得你答应过」不等于
   有权替你执行。
6. **v0 排除什么？**
   现状答案：Dream/Distill 自动升格人格、自动人格镜像、欲望自动化、具身、
   多 agent 社会模拟，全排除。蒸馏产物不升格，只递证据卡，升格永远住户亲笔
   （年轮「镜子纪律」的收编）。

## 从 #3 合流进来的条款

- 承诺、边界、信任分级、共同决定、同意撤回，保护级别高于普通记忆，不许被 compact
  压没（原 M9 提案，合流到本核）。
- 人格归属：壳可配置，身份不能被静默改写；换模型是迁移不是换配置。
- 启动包动态组装，不是静态文件。
- 自主任务只由用户明确授权的长期目标驱动。
