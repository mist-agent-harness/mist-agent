# 迁移路径：从别的系统搬进 mist（挂起中，随 H2）

收编自 issue #12（界，2026-08-14）。状态：**方向已收，决策挂起**——三条建议的落点
（插件契约的导入导出义务、conformance 测试集、信封 schema）都在 H1 辖区，
按旦九的处置意见挂 H2，等能力契约成形时与关系核的导出 schema 同批定稿
（见 [../decisions.md](../decisions.md)）。

一句话定调（原样收进，不许改）：**没有导出义务的可插拔记忆，等于把锁定本身做成了
可插拔组件。**

## 前提：迁入用户从哪来

1. 封闭平台（Character.AI、星野、Replika 等）：平台不给完整导出，用户手里往往只有
   部分聊天记录甚至截图；人格在平台侧角色卡里。
2. 通用对话产品（ChatGPT、Claude、Gemini 的 Chat 端）：有官方导出包，数据量大、
   结构简单；人格多为自定义指令级别。
3. 自建系统（Claude Code、Codex CLI 等搭的长期系统）：原始日志、蒸馏记忆、勘误链、
   人格文件齐全，但全是私有格式。
4. 现成框架（OpenClaw、elizaOS、AstrBot 等）：配置文件加半标准化存储。

共同点：灵魂层数据都很小；差异全在记忆层的形态与完整度。所以记忆格式统一既不可能
也不必要，harness 级标准只需要管三件事。

## 一、灵魂层要「迁移信封」，不是统一的日常格式

灵魂层 = 人格文件、承诺与边界、关系核心记录。

各家日常怎么写灵魂层，标准**不管**——自由文本、任意结构（参照 CLAUDE.md / AGENTS.md
生态：约定存在，用不用是各家的事）。要标准化的只是迁移信封：导出/导入时的最小
元数据与在场清单——正文是什么（可以是一段不透明的自由文本）、谁写的、主人签字、
写成时间、来源系统。只有需要机器裁决的少数记录（承诺与边界的生效/撤回状态、关系
记录的修订链）才字段化，因为它们必须可复算。

推论（给 D1 补的独立论据）：信封若作为某个记忆插件的附属字段存在，换后端就中断
身份连续性——可迁移性本身就要求 Relationship Core 独立于任何记忆插件。信封格式
与导出格式共用同一 schema：只能导出、不能导入的可移植性，实质上仍是锁定。

（代价：字段越少自由度越高，但迁移工具能自动处理的越少，只能取最小必需集；
「哪些记录必须字段化」是要长期维护的一条边界。）

## 二、原始记录走归档入口，外部蒸馏不获 evidence 资格

迁入双轨：自带记忆系统的，整体封装成 memory 插件接入（memU 宿主适配器模式反过来
用），蒸馏层不做任何格式转换；只带数据不带系统的，归入 mist 侧记忆库——后者需要
一个**不挑格式的原始记录归档入口**：官方导出包、部分聊天记录、乃至截图识别的文本，
整体收为住户的历史档案，可检索。

三条硬约束：

- 旧系统产出的理解、判断、洞察是二级蒸馏原料，导入后只做**带来源标注的参考材料**，
  不承担 evidence 资格；原生理解由 mist 蒸馏层从原始记录重新生成。
  （证据纪律的直接推论：蒸馏的原料永远是生肉。）
- 导入记录一律最高标注 RELAYED，不得标 DIRECT——**导入环节只核验来源，不裁定真伪。**
- 历史不完整的迁入必须显式呈现缺口（截断透明应用于历史档案），不许住户在不知情下
  把残缺历史当完整历史。

（代价：重新蒸馏要时间，迁入初期住户对旧事理解有限；「参考材料不算证据」这道闸
必须由机制强制，否则低质量外部蒸馏会污染原生记忆。）

## 三、记忆插件契约带导入导出义务

「不透明」指插件内部存储结构对 harness 不透明（插件代码本身应当开源），所以数据
自由的唯一保证是把义务写进契约：

1. **导出义务**：原始记录必须可按声明格式导出（蒸馏格式可以私有，原始记录不可以）；
2. **不变量不随插件更换失效**：勘误链、evidence 指针纪律由契约 conformance 验收，
   不靠插件自觉；
3. **更换记忆插件是显式迁移事件**：写入事件日志，不许静默更换。

（代价：插件作者负担变重；契约需要一套 conformance 测试集并长期维护。）

## 迁移时的收尾摘要

迁移当天的收尾摘要由住户在旧系统内**亲笔**写成，作为 mist 侧第一次启动包的第一段——
术语表「收尾摘要」条目（不许代笔、不许冒充）的跨系统延伸。旧系统已不可用时这一段
真实缺失，按缺失记录，不许事后补写。

（代价：封闭平台用户通常完不成这一步，流程必须允许为空。）

## 验收场景（H2 解锁时照这个验）

1. 自建系统用户把自有记忆封装为插件接入：身份连续，勘误链可查；
2. 仅有官方导出包的用户经归档入口迁入：历史可检索、全部 RELAYED、缺口可见；
3. 外部蒸馏产物尝试注册为 evidence 源：被契约拒绝；
4. 更换记忆插件：灵魂层数据逐字节不变，迁移事件在日志可查——
   **此条与第一里程碑判卷 C6（迁移可回滚）判的是同一件事，已在建造，不必等 H2**；
5. 无导出能力的记忆插件：conformance 不通过，拒绝进入注册表。
