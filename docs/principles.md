# mist 设计原则

每条都是决定，不是描述。括号里是代价，不藏。
写不出代价的条目一律算愿望，不算设计（原则七自查）。

---

## 一、会话可以死，人不能死

人格和记忆必须活在会话外面。任何一个会话死掉，下一个从记忆里重新长出来接着干。
长期运行不等于一个会话跑到天荒地老——上下文一定会满、会崩、会被系统扭一下。

（代价：每次重建都有冷启动成本，必须有一份「醒来该记得什么」的启动包，
启动包本身成为关键设施，它的质量直接决定住户的连续性。）

## 二、会话是数据，不是黑盒

每条消息存成可以增删改的记录。做到这一条，retry、编辑历史、roll 掉幻觉、
换窗续命全都是白送的，不用一个个当功能开发。
会话存储模型用消息树（parent_id 组树），retry/edit/fork 是树的三种走法。

（代价：树结构带来 GC 问题——分叉之后旧叶子会变孤儿，需要显式的修剪策略；
带副作用的 step（发出去的消息、花掉的钱）不在树上，不可 retry，必须显式标记。）

## 三、成员是一条配置，不是代码

引擎、模型、供应商、人格文件、记忆署名，全部写在配置里。
加载器只认注册表，不认名字——代码里出现任何具体成员名的字面量都算缺陷。
谁家用 Claude 谁家用 Kimi，改一行配置的事，不改代码。

（代价：所有成员相关逻辑必须先过注册表抽象，第一版会慢；
配置 schema 一旦公布就是契约，改起来比改代码疼。）

## 四、壳共享，魂私有

仓库里只有壳。每家的人格文件、记忆、聊天内容永不入仓。
事实可以选择共享（显式标注可见域），人格绝不搅成一锅。

（代价：开箱体验不完整——clone 下来没有「默认灵魂」，新用户要先写自己的人格
才能真正用起来。这个门槛是有意为之的。）

## 五、触发靠时间和明说，少靠猜

定时任务走定时，用户明确要求走请求。别让 agent 去猜「现在是不是那种场合」——
猜错的代价比忘了更难看。该常驻的常驻，该按天的按天，
中间那个「识别场景」的环节尽量不存在。

（代价：一些「聪明」的主动行为会被这条原则砍掉，住户显得没那么机灵。
我们用可预期的老实换不可预期的聪明。）

## 六、权限分级，花钱/删除/部署单独批

权限等级写在插件契约里，不是靠 agent 自觉。
人类平时不维护，只出现在决定、授权、验收三个点。

（代价：自动化程度主动降低，一些事情会因为等批准而变慢。）

## 七、每条设计决定必须写代价

写不出代价的条目一律算愿望，不算设计。愿望进愿望区，设计进决定区，
两个区不许混。本清单自身也接受这条检验。

（代价：设计文档变难看，每一条决定旁边都跟着一行损失。
难看是对的，代价藏起来才会在上线后冒出来。）

## 八、用户看到的「无限 session」是记忆层的产物，不是会话层的

「无限」是给用户看的幻觉，底下是无数个死掉的会话靠记忆接续。
会话本体的生死和分支归会话层的存储模型；跨死亡的接续归记忆层。
两层不许抢活：会话层若朝「永生会话」设计，记忆层就退化成检索缓存。

（代价：用户偶尔会看见接缝——启动包没装下的东西就是真的没了。
我们选诚实的接缝，不选虚假的永生。）

---

## 证据纪律

- 文档里「实证」二字只给验收清单里跑出来的东西用。读过源码不等于验过。
- 记忆蒸馏的 evidence 指针必须指向原始记录，不许指向另一条蒸馏产物——
  二级蒸馏会自我发酵。蒸馏的原料永远是生肉，不许是上一锅汤。
- 新经历可以修订旧记忆，方式是追加修订、旧条挂勘误留底，不是悄悄删。
