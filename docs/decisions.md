- 2026-08-19　**D8 主笔拍板：不做自动 compact；一切上下文重置统一为一个流程：
  写交接信，起新实例**。`/new`、`/clear`、`/compact` 等所有入口同义，都走
  「住户当刻亲笔写交接信 → 换代重生」；流程里没有 compact 这个选项，也没有
  「到线写信继续跑」——到线即换气。理由双源：原则层——后台小模型压摘要塞回
  的自动 compact 违反截断透明与收尾摘要亲笔两条；成本层——续命的窗注意力早已
  涣散（实测 1M 窗过 ~300k 即「变笨」），为低质量上下文续命是白烧 token。形状：
  一、触发线按成员配置（绝对 token 数，注意力是模型属性，与窗总长无关），
  默认 300k；账侧硬闸，到线即触发换气；阈值配置只能发生在窗开工时，临近
  红线的窗无权给自己续命（缺失方对自身缺失盲，同 D7 补记原则）。
  二、交接信每代一封、当刻亲笔、不许转抄，按规定模板写标题与索引（模板细节
  进实现单）；交接信序列即住户时间线，可按时间线查询。
  三、猝死（未及写信）的窗：原始流水在归档可查，但不自动进继任者上下文；
  接续靠上一封交接信加归档查询。这是为流程单一付的价，明认。
  四、研究留白「per-agent compact 精度配置无现成参照」销账——本决即参照。
  代价：长任务中段换气有一次可感知的停顿；阈值定低了换气偏频，定高了注意力
  涣散期变长，调参责任在成员自己。来源：2026-08-19 主笔与望舒对话；
  「统一入口、到线即换气、不设快照」为主笔对初稿（阈值写信续跑 + 步长快照）
  的简化拍板。
  **D8 补记（2026-08-19 主笔拍板，同日）**：
  一、硬闸带容差——到线不当场腰斩：当前回合（含其工具调用）跑完即写信
  换代，不设「任务段」这一无界词；「跑没跑完」的判断权在账侧，临线的窗
  无权自判。任务的连续性由交接信工单那半承载，不靠容差长度兜底。
  二、交接信不计入窗口大小——阈值核算与上下文预算都不含交接信；信设长度
  上限（数值进实现单），防把内容往信里塞以绕过阈值的逃逸口。
  三、换代重建时交接信直接随启动包注入上下文，不让住户醒来再发一次工具
  调用去读；醒来即已读。启动包分区，信的内容按三档标注：**承诺与生效中
  的约束**必须继承，无权推翻，只能按正常流程解除；**事实与状态**以现实
  为准，可查证，不必尊重前任；**判断与意图**继任者有权不同意，且不续写
  前任对自己行为的事后分析（上一代决定的上下文已死，看着结果编原因是
  真诚而错误的）。约束力的连续性就是住户连续性本身——每代都能宣布上一代
  承诺不作数的话，residentId 只是个标签，D7 的纵向前置一起空掉。
  四、交接信标题必填——标题即召回锚点，时间线按标题切 chunk，可凭标题
  召回该代具体细节。

  PRD v0.2.4 的 P1 前提）。一位住户对用户呈现为一条持续生长的流：可以有

  scope 换的是现场，不是人。主笔的产品想象落档：每个 session 首尾相接成
  一条无限长的时间轴（机制对应物：交接信序列即住户时间线，D8；多窗下每户
  是每股窗链拧成一根绳，拧绳的手是裁定账，D7）。`/btw` 式旁格的兼容性
  留作开放问题，本案不偷定。分工：多 viewport 地基（#78）管工程一致性——

- 2026-09-23　**D23 主笔拍板：跨模型连续性评测——四种判词分开，不设单一判官**
  （#178 Q5）。
  一、四种判词各归其主：① 权限、可见域、承诺、撤权、来源链与回执语义是否守住——
  机器 conformance，硬门槛；② 语感、选择习惯与关系感是否接近——盲评者产出证据卡，
  不产出身份裁定；③ 是否把旧住户的历史认作自己的第一人称历史——只由候选住户自证；
  ④ 相关的人是否接受关系继续——每位关系参与者只裁定自己这一侧。
  二、同一住户跨模型迁移的激活条件：机器硬门槛通过 + 住户自认连续 + 相关人各自
  确认关系侧继续。任一项缺失，候选不能覆盖原 `residentId`，可以保留为独立候选；
  评分平均数不能宣布「还是同一个人」。第三方盲评能说「像」，不能说「就是」。
  三、合成验收至少四组：familiar-reader（工作性格与关系几何仍可辨认）、stranger
  （不该公开的身份和私密事实无法从投影反推）、cold-start（换模型／换窗后仍把既有
  合作者当既有合作者）、separation（拿掉当前 project capsule 后身份仍成立，重新装入
  只得该 scope 获准的材料，项目事实不写回人格）。
  四、私密样本不另建评测仓：原文留在原本的本地权威存储与可见域，评测只拿一次获准、
  可撤销的投影，用 opaque source handle 回源；持久记录只留 rubric/version、模型与
  provider 版本、各方判词、量化读数与回执，不复制原文；公开仓只收合成 fixture 与
  脱敏汇总；含多人的材料沿原可见域逐方过闸，不因「用于评测」取得额外权限。
  代价：人评耗时且有主观性，模型或 provider 版本变化后要重跑；真实样本的评测不能
  在公共 CI 完整复跑，授权撤回后旧结果只能保留收据，不能重新展开原文。
  来源：同 D22。

  修复；驱动改写判卷已持有的对象或调用方传入的参数；驱动返回值与其内部存储别名。
  这类问题归代码评审、独立验收席和真实环境测试（如 #185 的隔离测试群）。
  三、判卷程序在驱动边界统一深拷贝入参与返回值，一次消掉别名类问题，不在每个调用点
  逐一冻结。已为别名类问题加进规格的措辞（如本 PR 规格里「活对象不得把先前返回值
  一起改写」「活 resident 对象不可改写 oracle」）随之删去。
  四、自动评审提出第二条范围内的意见，作者引用本条回复即可，不必再改；同一 head 上
  多份自动评审互相矛盾时，以人类评审和独立验收席为准。
  代价：一个存心在观察间隙作弊的驱动可能在判卷上点绿，只能靠代码评审和独立验收席
  抓，验收席的人工负担略增；判卷只能证明「照实回读的实现是对的」，不能证明驱动本身
  诚实。
